# 具身智能精密装配赛程序

比赛入口实现完整的评分展示闭环：确认连接参数 → TCP 请求 VisionMaster 任务卡 1 → 千问视觉流式推理与文本输出 → TCP 请求任务卡 2 → 按智能体方案请求物块和托盘坐标 → ARCS 虚拟机械臂六步装配与原生日志。

任务卡一、任务卡二均为裁判随机图片：程序先完成任务卡一的识别和文本输出，再解析任务卡二并按本次随机顺序装配；项目书示例仅用于测试，不参与正式运行。

VisionMaster 在本地文件夹保存任务卡图片后，通过 TCP 回传完整绝对路径；Python 读取该 JPG/PNG 文件并交给 Qwen。VisionMaster 与 Python 应运行在同一台 Windows 主机，或使用路径一致的共享文件夹。

## 运行一键比赛

首次运行安装基础依赖：

```powershell
python -m pip install -e .
```

启动入口：

```powershell
python scripts/run_competition.py
```

点击“**一键比赛**”，填写百炼 API Key、VisionMaster 地址、ARCS/VMware 地址和 JSON-RPC 端口后，点击“**确认并开始比赛**”。API Key 只保存在本次运行内存中。

进入主界面后比赛流程自动开始：

1. 程序依次向 VisionMaster 发送 `duqu` 读取任务卡 1、任务卡 2；
2. 任务卡二解析后，按本次随机方案分别发送六次 `wukuai,编码` 和六次 `tuopan,编码`，再自动完成六步装配；
3. 左侧“**五分钟展示**”显示千问流式过程、文本结果、触发字符和执行状态；任务卡图片统一在 VisionMaster 中展示；
4. 左侧“**打印日志**”选择一个宿主机文件夹，生成 VisionMaster、LLM 和 ARCS 原生 Trace 三份独立 TXT；
5. 两个页面共用右上角五分钟倒计时，切换和导出日志不会重置计时；倒计时归零时禁止新动作并向 ARCS 请求紧急停止。

仿真演示不再调用麦克风、ASR、TTS 或扬声器。

ARCS原生日志继续写入ARCS系统。比赛结束后，宿主机通过现有ARCS IP和30004端口调用 `rob1.Trace.peek`，只截取本次 `COMPETITION_START` 与 `COMPETITION_END` 标记之间的ARCS原生记录并导出；不需要SSH账号、虚拟机密码或额外端口。如果当前ARCS版本不返回普通 `Trace.textmsg`，程序会明确拒绝生成第三份文件，用户需改用ARCS界面的原生日志下载功能。

## 关键评分要求已落实

- 比赛模式校验 VM 报文，例如 `#0;1;-1;10;`，并保留末尾分号；
- 每步在 ARCS 原生日志中记录本地固定工位数据、智能体触发字符和回归初始位姿后的 TCP 坐标；
- 第一装配步前先运动到规定初始关节位姿 `(0°, 0°, 90°, 0°, 90°, 0°)`；
- 取放 TCP 高度为基座平面 `10 mm`，安全高度为 `120 mm`；
- 每一步均为“接近物料 → 到位 → 离开 → 接近托盘 → 到位 → 离开 → 回初始位姿”。

三份宿主机日志用于提交和留档。比赛时如评分细则要求，仍须在屏幕共享中展示 VisionMaster 原生流程界面与 ARCS 原生日志区。
