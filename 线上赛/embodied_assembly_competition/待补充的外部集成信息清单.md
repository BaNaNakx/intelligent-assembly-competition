# 赛前待补充与验证清单

## 当前仍需提供的资料

只需完成一次真实 VisionMaster 联调，并保留：

1. VM 收到 `GET_TASK_CARD_1`、`GET_TASK_CARD_2`、`GET_COORDINATES` 三条请求的界面截图；
2. 一张随机任务卡的完整绝对路径响应，确认 Python 可读取 VM 保存的图片；
3. 一次真实运行中 VisionMaster 发出的 12 条坐标报文原文，确认每条均为 `#0;X;Y;RZ`；
4. 若图片路径或坐标响应带换行符、长度头或其他前后缀，记录规则。

程序已经固定通过 TCP 发送请求、接收 VM 保存图片的绝对路径并读取 PNG/JPG。上述资料只用于核验 TCP 连接边界；若与当前规则不同，只调整 `src/assembly/visionmaster_tcp.py`。

## 随机任务卡处理规则

- 任务卡一和任务卡二都由裁判随机生成，正式程序不使用项目书示例内容；
- 程序先识别并输出本次任务卡一的场景语义与物品；
- 输出“任务已完成”后，才识别本次任务卡二；
- Qwen 从任务卡二图片动态提取本次六条装配顺序，再生成对应的触发码和机械臂执行顺序；
- 不会在任务卡一完成前启动任务卡二识别或 ARCS 装配。

固定不变的只有项目书规定的 12 条颜色坐标、颜色触发码、初始位姿和每步运动路径。

## 已完成并验证

- 一键比赛窗口、纯文本“小具同学 → 准备就绪 → 执行任务”和 5 分钟倒计时；
- Qwen `qwen3.7-plus` 图片识别、流式日志、随机任务卡二六步骤解析和触发码校验；
- TCP 请求—响应、本地 PNG/JPG 任务卡路径读取，以及原始 `#0;X;Y;RZ` 坐标报文解析；
- ARCS JSON-RPC 与 `rob1` 的真实连接、上电后初始位姿运动和两次完整六步仿真；
- 每步均无碰撞并返回初始关节 `(0°, 0°, 90°, 0°, 90°, 0°)`。

- API Key、账号密码或许可证；
- 方块/托盘尺寸、夹爪/吸盘、IO 或附着/释放接口；
- ARCS SDK、插件安装包、IP/端口资料或机器人初始位姿截图。

比赛时 API Key 在一键比赛窗口临时填写，不写入任何文件。
